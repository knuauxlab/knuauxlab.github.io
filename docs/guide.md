## 1. 한눈에 보기

| 항목 | 내용 |
|---|---|
| 홈페이지 주소 | https://knuauxlab.github.io/lab_website/ |
| 관리 화면 주소 | https://knuauxlab.github.io/lab_website/admin/ |
| 저장소(코드와 내용이 있는 곳) | https://github.com/knuauxlab/lab_website |
| 소유 계정 | `knuauxlab` (GitHub 조직) |
| 로그인 방법 | GitHub **토큰**(아래 2장) |
| 반영 시간 | 저장 후 **1~2분** |

**동작 원리.** 관리 화면에서 저장하면 GitHub 저장소에 파일이 바뀌고, 자동으로 사이트가 다시 만들어져(빌드) 공개된다. 이 과정은 사람이 따로 할 일이 없다.

**중요한 점.**
- 저장은 미리보기가 아니라 **바로 공개**다. 아직 보여주고 싶지 않은 글은 `임시 저장`을 체크한다.
- 형식이 잘못된 내용은 사이트에 올라가지 않는다. 사이트는 이전 상태를 유지하고 저장소의 Actions 탭에 빨간 표시가 뜬다(6장 참고).

## 2. 토큰 만들기와 갱신하기

관리 화면은 비밀번호 대신 **토큰**(긴 문자열)으로 로그인한다. 토큰은 GitHub가 발급하는 임시 열쇠다. **만료일이 있어서 주기적으로 새로 만들어야 한다.**

### 2-1. 토큰 만들기 (처음, 그리고 만료됐을 때)

1. GitHub에 **저장소에 쓸 수 있는 계정**(조직 `knuauxlab`의 owner 또는 Write 권한이 있는 계정)으로 로그인한다.
2. 오른쪽 위 프로필 사진 → **Settings** → 왼쪽 맨 아래 **Developer settings** → **Personal access tokens** → **Fine-grained tokens** → **Generate new token**을 누른다.

   > **[캡처 필요 01]** Developer settings에서 Fine-grained tokens 화면

3. 아래처럼 입력한다.

   | 칸 | 입력값 |
   |---|---|
   | Token name | `aux-lab-cms` |
   | Description | `AUX Lab 홈페이지 편집 화면(/admin/) 로그인용` |
   | **Resource owner** | **`knuauxlab`** (개인 계정이 아니다) |
   | Expiration | 가능한 가장 긴 기간(최대 약 1년) |
   | Repository access | **Only select repositories** → `knuauxlab/lab_website` 하나만 선택 |

   > **[캡처 필요 02]** Resource owner, Expiration, Repository access를 채운 화면

4. **Permissions → Repository permissions**에서 **Contents**를 **Read and write**로 바꾼다. (Metadata는 자동으로 Read-only가 되며 그대로 둔다.)

   - 화면 가운데의 **Add permissions** 버튼을 누르고 `Contents`를 찾아 체크하면 줄이 추가된다. 그 줄의 드롭다운이 처음에는 Read-only이니 **Read and write**로 바꿔야 한다.
   - **이 단계를 빼먹으면 로그인은 되는데 저장할 때 "Resource not accessible by personal access token" 오류가 난다.**

   > **[캡처 필요 03]** Contents 줄이 Read and write로 설정된 화면

5. 맨 아래 **Generate token**을 누른다. 화면에 `github_pat_...`로 시작하는 문자열이 한 번만 나온다. **바로 복사한다.** 이 화면을 닫으면 다시 볼 수 없다.

   > **[캡처 필요 04]** 토큰이 생성된 화면 (**토큰 값은 반드시 가리고** 캡처)

6. 조직이 토큰 승인을 요구하면 상태가 "승인 대기"로 보인다. 조직 owner가 **조직 Settings → Personal access tokens → Pending requests**에서 승인해야 쓰기가 된다.

### 2-2. 만료일 관리 (가장 중요)

토큰이 만료되면 저장할 때 오류가 나거나 로그인 화면으로 돌아간다. **이미 올라간 내용은 그대로이고 잃는 것은 없다.** 그래도 갑자기 막히지 않게 아래 두 가지를 해 둔다.

- 만료일을 아래 표에 적어 두고, **만료 2주 전**에 달력 알림을 건다.
- 토큰 목록 화면(Settings → Developer settings → Fine-grained tokens)에서 언제든 만료일을 확인할 수 있다.

| 기록 | 값 |
|---|---|
| 토큰 이름 | `aux-lab-cms` |
| 만든 계정 | (적어 두기) |
| 만든 날짜 | (적어 두기) |
| **만료일** | (적어 두기) |

### 2-3. 토큰 갱신하기

만료 전에 새로 만들고, 예전 것을 지우면 된다.

1. 2-1의 순서대로 **새 토큰을 만든다.** (이름은 `aux-lab-cms-2027`처럼 연도를 붙이면 구분하기 쉽다.)
2. 관리 화면에서 **로그아웃**하고 새 토큰으로 다시 로그인한다. (3장)
3. 저장이 되는지 한 번 확인한다.
4. 예전 토큰은 토큰 목록에서 **Delete**로 지운다.

### 2-4. 토큰을 다룰 때 주의

- 토큰은 **비밀번호와 같다.** 메신저, 이메일, 사진, 이 문서에 값을 적지 않는다.
- 유출이 의심되면 토큰 목록에서 즉시 **Delete**하고 새로 만든다.
- 공용 컴퓨터에서 로그인했다면, 쓰고 나서 관리 화면에서 로그아웃한다.

## 3. 관리 화면 로그인

1. https://knuauxlab.github.io/lab_website/admin/ 에 접속한다.
2. **액세스 토큰으로 로그인**을 누른다. (`GitHub로 로그인` 버튼은 쓰지 않는다. 지금은 토큰 방식만 지원한다.)

   > **[캡처 필요 05]** 관리 화면 첫 로그인 화면

3. 복사해 둔 토큰(`github_pat_...`)을 붙여넣고 로그인한다.
4. 토큰은 **그 브라우저에만 저장**되어 다음부터는 다시 입력하지 않아도 된다. 다른 컴퓨터에서는 토큰을 다시 넣어야 한다.

로그인하면 왼쪽에 **소식, 논문, 프로젝트, 구성원, 연구 분야, 연구실 정보** 메뉴가 보인다.

> **[캡처 필요 06]** 로그인 후 전체 화면 (왼쪽 메뉴가 보이게)

## 4. 내용 고치기

### 4-1. 기본 사용법 (모든 메뉴 공통)

- **새로 만들기:** 왼쪽 메뉴에서 항목을 고르고 오른쪽 위 **새 글**(또는 `+`)을 누른다.
- **고치기:** 목록에서 항목을 누르면 입력 폼이 열린다.
- **저장:** 오른쪽 위 **저장**(Publish)을 누른다. 누르는 순간 공개된다.
- **지우기:** 항목을 열어 오른쪽 위 메뉴(`⋯`)에서 삭제한다. 지우기 전에 **임시 저장** 체크로 숨기는 것도 방법이다.
- **임시 저장:** 폼의 `임시 저장(사이트에 표시하지 않음)`을 체크하고 저장하면 사이트에 나타나지 않는다. 다 쓰고 나서 체크를 풀면 공개된다.
- 필수 칸(제목 등)이 비면 저장되지 않는다. 형식이 틀린 칸은 빨간 안내가 뜬다.

> **[캡처 필요 07]** 항목 편집 화면 (저장 버튼, 임시 저장 체크 위치가 보이게)

## 5. 저장하고 반영 확인하기

1. 관리 화면에서 **저장**을 누른다.
2. **1~2분** 기다린다. 사이트가 다시 만들어지는 시간이다.
3. 홈페이지에서 **Ctrl+Shift+R**(Mac은 Cmd+Shift+R)로 강력 새로고침한다.
4. 바뀐 내용이 보이면 끝이다.

**왜 바로 안 보이나?** 두 가지 대기 시간이 겹친다. (1) 사이트를 다시 만들고 올리는 시간 약 1~2분, (2) 브라우저가 옛 페이지를 최대 10분 보관하는 캐시. 저장 직후 일반 새로고침으로는 옛 화면이 보일 수 있으니 강력 새로고침을 쓴다.

**배포가 끝났는지 확인하려면:** 저장소 https://github.com/knuauxlab/lab_website 의 **Actions** 탭을 본다. 가장 위의 실행이 초록색 체크면 끝, 빨간색 X면 실패(6장).

> **[캡처 필요 12]** Actions 탭 (성공과 실패 표시가 보이게)

## 6. 자주 나는 문제와 해결

### 6-1. "Resource not accessible by personal access token" (저장할 때 오류)

로그인과 목록 보기는 되는데 **저장만 안 될 때**다. 토큰에 쓰기 권한이 없다는 뜻이다. 아래를 순서대로 본다.

1. **Contents 권한:** 토큰 상세 화면(Settings → Developer settings → Fine-grained tokens → 토큰 이름)에서 Repository permissions의 **Contents가 `Read and write`**인지 확인한다. 비어 있거나 `Read-only`이면 **Add permissions**로 추가하거나 바꾸고 **Update**를 누른다.
2. **Resource owner:** 토큰 화면 위에 **`Access on knuauxlab`**으로 나와야 한다. 개인 계정으로 나오면 이 화면에서 바꿀 수 없으니 토큰을 새로 만든다.
3. **저장소 선택:** Repository access에 `knuauxlab/lab_website`가 있는지 본다.
4. **조직 승인:** 조직 Settings → Personal access tokens → Pending requests에 이 토큰이 있으면 승인한다.
5. **계정 권한:** 토큰을 만든 계정이 저장소에 **쓰기 권한**이 있는지 확인한다.

고친 뒤 관리 화면을 새로고침하거나 로그아웃 후 다시 로그인하고 저장한다.

### 6-2. 저장했는데 사이트가 안 바뀐다 (Actions에 빨간 X)

저장은 GitHub에 올라갔지만 **사이트를 다시 만드는 단계가 실패**한 경우다. 이때 사이트는 **이전 상태 그대로**이고 망가지지 않는다.

1. 저장소의 **Actions** 탭에서 가장 위 실행을 연다.
2. 실패한 단계(`Install, build, check links, and upload site`)를 열어 **오류 메시지**를 읽는다. 한국어로 무엇을 고칠지 적혀 있다. 예:
   - `end: 월은 2026-04 형식으로 입력하세요.` → 프로젝트의 종료 칸 형식이 틀렸다.
   - `날짜는 2026-04 또는 2026-04-15 형식으로 입력하세요.` → 소식 날짜 형식이 틀렸다.
   - `https:// 로 시작하는 올바른 주소를 입력하세요.` → 링크에 `https://`가 빠졌다.
3. 해당 항목을 관리 화면에서 고치고 다시 저장한다. 성공하면 사이트가 갱신된다.
4. 이유를 모르겠으면 오류 메시지를 복사해 개발자에게 전달한다.

> **[캡처 필요 13]** 실패한 Actions 실행의 오류 메시지 화면

### 6-3. 날짜 형식 오류

| 칸 | 올바른 형식 | 틀린 예 |
|---|---|---|
| 소식 날짜 | `2026-04` 또는 `2026-04-15` | `2026.04`, `26-4`, `2026-4-1`, `4월` |
| 프로젝트 시작/종료 | `2026-04` | `2026-04-15`(일 포함), `2026.04` |
| 존재하지 않는 날짜 | | `2026-13`, `2026-02-30` |

- 숫자는 **두 자리**(`04`, `09`)로 쓰고 구분은 **하이픈(`-`)**이다.
- 종료일을 모르면 **비워 둔다.** 아무 값이나 넣지 않는다.

### 6-4. 저장은 됐는데 화면에 안 보인다

차례로 확인한다.

1. **1~2분** 지났는가? (5장)
2. **강력 새로고침**(Ctrl+Shift+R)을 했는가? 브라우저가 옛 화면을 10분까지 보관한다.
3. Actions 탭이 **초록색**인가? 빨간색이면 6-2.
4. 폼에서 **`임시 저장`이 체크**되어 있지 않은가? 체크된 항목은 사이트에 나타나지 않는다.
5. 분류, 직위, 연도 같은 칸이 의도한 값인가? (예: 구성원의 상태가 `졸업생`이면 현재 구성원 목록에 없다.)
6. 홈 화면의 소식은 **최근 5개**만 보인다. 더 오래된 소식은 Album 페이지에 있다.

### 6-5. 로그인이 안 된다

- 토큰 **만료**: 2-2에서 적어 둔 만료일을 확인하고, 만료됐으면 새로 만든다(2-3).
- 토큰을 **잘못 복사**함(앞뒤 공백, 일부 누락): 다시 복사해서 붙여넣는다.
- 다른 컴퓨터나 브라우저에서는 토큰을 새로 입력해야 한다.
- `GitHub로 로그인` 버튼은 쓸 수 없다. **`액세스 토큰으로 로그인`**을 누른다.

### 6-6. 사진이 이상하게 나온다

- 구성원 사진은 **얼굴이 가운데 오는 정사각형**으로 올린다. 가로로 긴 사진은 얼굴이 잘릴 수 있다.
- 사진 용량이 아주 크면(수십 MB) 올리기가 오래 걸린다. 사진은 몇 MB 이하로 줄여서 올리는 것이 좋다.

### 6-7. 실수로 잘못 저장했다

저장할 때마다 GitHub에 **기록이 남으므로 이전 상태로 돌릴 수 있다.**

1. 저장소의 해당 파일 페이지에서 **History**를 연다.
2. 이전 버전을 열어 내용을 확인하고, 관리 화면에서 그 값으로 다시 고쳐 저장한다.
3. 복구가 어려우면 개발자에게 부탁한다. 개발자는 해당 커밋을 되돌릴 수 있다.
